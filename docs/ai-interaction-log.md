## 3. 地图选型与迭代（2026-11-21 ～ 11-24）

### 3.1 第一轮：公开地图数据

**用户请求（摘录）**

> “我们这个项目里的地图是什么样的？如何存储、如何展示？障碍物位置怎么知道？”

**AI 动作**

- 解释“底图 / 路网 / 路况”三层结构；
- 先尝试 OpenStreetMap 数据，生成真实建筑轮廓与道路；
- 验证连通性、封路绕行、单入口。

**用户反馈（摘录）**

> “其实感觉你这个地图跟我给你提供的北邮海淀校区地图不太能对得上，用这个代码吧：map_design.7z。”

### 3.2 第二轮：队友 map_design 底图

**AI 动作**

- 解压队友 `map_design.7z`（系统 tar，排除内嵌 Python 运行时）；
- 读取 `structure.json`，提取地点与建筑坐标；
- 使用队友标注的《北邮西土城路校区示意图》作为底图；
- 前端支持 `background_image`，FastAPI 同源托管 `/vendor`；
- 修复接口漏返回 `background_image` 导致“页面只有几个点、没有底图”的问题。

### 3.3 第三轮：路线必须沿道路

**用户反馈（摘录）**

> “你这个在地图上画的连接科研楼和东门的直线就是路径吗？中间还有很多建筑啊？”

**AI 动作**

- 承认点对点直线会穿楼；
- 改为 6 纵 × 10 横道路网格；
- 站点用短入口线接入最近路口；
- 生成 `docs/campus-map-preview.svg` 供用户可视化确认。

**用户反馈（摘录）**

> “有一些路线直接穿过了整个教三楼，但也没关系，因为教三楼中间也有通道，原地图没标出来，后续有需要再改。”

**决策**：接受当前网格，暂不返工。

### 3.4 第四轮：扩展到 80 个地点

**用户请求（摘录）**

> “我感觉我们现在的地点还是太少了，地图上很多地点都没有标记出来，路线也没有添加进去。”

**AI 动作**

- 分析队友数据：41 栋建筑 + 39 个服务点 + 6 个校门；
- 全部接入道路网格：
  - 217 个节点、261 段道路；
  - 80 个可交互地点 + 6 个校门；
- 建筑显示名称，服务点小蓝点 + 悬停名称；
- 下拉框按“教学与科研 / 学生公寓 / 生活服务 / 场馆与后勤”分组。

### 验证

- 80 个地点两两可达；
- 旧 6 个地点 ID 保留；
- 图书馆单入口；
- 前端编译通过。

## 4. 解析、补问与评测（2026-11-21）

### 用户请求（摘录）

> “这个 20 条解析样例集是什么意思？”

**AI 动作**

- 解释：20 句需求 + 人工标准答案 + 自动评测脚本；
- 新增 `backend/tests/parse_cases.json` 与 `eval_parse.py`；
- 首次评测 **17/20**，发现三个真实问题：
  1. 缺取货点自动猜；
  2. 未知取货点被配送点顶替；
  3. 白名单外配送点被静默丢弃；
- 修改 `parser.py`：
  - 缺取货点 → 提示补充；
  - 未知取货点 → 取货点留空；
  - 新增 `_unknown_delivery_locations`；
- 重新评测 **20/20**。

### 用户请求（摘录）

> “我有点没懂，这个照片上传 + 视觉异常分析，需要给我的校园都拍张照片吗？”

**AI 动作**

- 解释照片只拍异常点，不需要拍遍校园，不需要训练模型；
- 说明 DeepSeek 文本模型不能看图，视觉需要另外的 VLM；
- 记录为后续规划。

### DeepSeek 接入

**用户反馈（摘录）**

> “我已经有 deepseek 模型的 API key 了，在 `.env` 文件里填好了。”

**AI 动作**

- 验证配置：`base_url=https://api.deepseek.com/v1`、`model=deepseek-chat`；
- 单条解析返回 `llm:deepseek-chat`；
- 20 条评测：模型 **20/20**（18 条模型 + 2 条规则兜底）；
- 接口测试默认禁用外部模型，避免 pytest 依赖网络。

## 9. 交互记录小结

| 阶段 | 用户主要请求 | AI 主要产出 | 验证方式 |
| --- | --- | --- | --- |
| 需求理解 | 开始开发、边做边聊 | 代码盘点、链路修复、测试 | py_compile / ASGI |
| 工程化 | 启动包 | README、脚本、`.env` | 命令实测 |
| 地图 | 真实布局、不要穿楼、地点太少 | OSM → 队友底图 → 80 地点 | 连通性、前端编译、预览 |
| 解析 | 20 条样例、模型接入 | 样例集、解析修复、DeepSeek | 20/20 |
| 补问 | 页面逐项追问 | 问题卡片、创建拦截 | 编译、产物检查 |
| Agent | 多 Agent 体现在哪 | 三 Agent、痕迹、时间线 | trace 查询、页面 |
| 管理员 | 接单/状态/备注 | 管理页、接口、表 | ADMIN OK |
| 合并 | 拉队友提交 | 合并、冲突解决、夹具 | 全量测试 |
| 文档 | 总结、PPT 大纲 | 四份文档 + HTML | 文件检查 |

### 关键原则

1. **AI 产出必须验证**：编译、测试、接口检查、页面确认；
2. **用户拍板关键取舍**：地图选型、照片暂缓、是否引入框架；
3. **不虚构**：模型失败写“兜底”，未完成写“后续规划”，不编造效率百分比；
4. **痕迹可查**：Agent 调用、Git 提交、测试输出都能回溯。
